# 0.0.3 review

This release applies MPL-2.0 to the core and facade. The SDK uses the same
license. Older registry archives retain their original terms.

## Readability

Shortened repeated explanations and change histories in library comments.
Kept wire formulas, verification order, compatibility boundaries and safety
contracts. Corrected outdated hybrid support and claim-derivation documentation.
Public policy digest comparison is no longer described as providing a general
constant-time guarantee for secret inputs.

## Reproduced defects and fixes

- `mlkem_p256::Keypair` derived `Debug` printed the 64-byte ML-KEM seed through
  `Zeroizing`. Its manual implementation now redacts that field.
- `seal_p256` accepted a compressed recipient point, but the recipient derived
  its KDF input from an uncompressed point. It now requires the 65-byte
  uncompressed representation returned by `P256Agreement::public_key`.
- `seal` accepted X25519 coordinate aliases with identical DH results and
  different KDF bytes. It now requires a coordinate below `2^255 - 19`.
  Low-level X25519 agreement still accepts RFC 7748 encodings.

All three regression tests failed before the fixes. Each includes a valid
round-trip or a check of the exposed seed; they pass after the fixes. Rejecting
previously unopenable recipient encodings changes input validation, not KDF,
nonce or authenticated wire formulas. Existing canonical recipients retain
their representation and RNG consumption order.

## Checks and limits

The review used separate public source checkouts. Native tests include existing
KAT and golden vectors, malformed signed headers, low-order keys and parser
mutation tests. Clippy, Rustdoc with warnings denied, a pure-core WASM build,
and dependency license/advisory/source checks passed locally.

SDK checks cover 10,928 envelope bit mutations, 1,366 truncations, purpose and
context binding, low-order keys, the 16 MiB boundary, and simulated entropy
failure on each of the two RNG draws. Eight Python ABI tests use a real native
library and valid caller-owned buffers, including rejection without output
writes and allowed input/output overlap after copying.

These are implementation checks, not an independent cryptographic audit.
An additional audit reproduced the defects above, but its extended fuzzing
continuation was interrupted by a platform filter. No completed instrumented
fuzz campaign or timing/side-channel proof is claimed here.
