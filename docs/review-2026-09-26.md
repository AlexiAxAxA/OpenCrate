# MPL release and cryptographic review

This release applies MPL-2.0 to the core and facade. The SDK uses the same
license. Older registry archives retain their original terms.

## Readability

Shortened repeated explanations and change histories in library comments.
Kept wire formulas, verification order, compatibility boundaries and safety
contracts. Corrected outdated hybrid support and claim-derivation documentation.
Public policy digest comparison is no longer described as providing a general
constant-time guarantee for secret inputs.

## Reproduced defects and fixes

- `mlkem_p256::Keypair` derived `Debug` printed the 64-byte ML-KEM seed through
  `Zeroizing`. Its manual implementation explicitly redacts both private fields
  in normal and pretty output.
- `seal_p256` accepted a compressed recipient point, but the recipient derived
  its KDF input from an uncompressed point. It now requires the 65-byte
  uncompressed representation returned by `P256Agreement::public_key`.
- DH Seal accepted X25519 coordinate aliases with identical DH results and
  different KDF bytes. It now requires a coordinate below `2^255 - 19`.
  Recipient and ephemeral encodings are now checked before DH/KDF, including
  keys supplied by a `KeyAgreement` provider. P-256 points must also be valid
  points on the curve. Invalid recipient encodings are rejected before RNG use.
  Low-level X25519 agreement still accepts RFC 7748 encodings.

All ten regression tests failed against the original public implementation and
pass after the fixes. They check both Debug formats, modulus and high-bit aliases,
invalid P-256 points, provider calls and RNG consumption. Rejecting
previously unopenable recipient encodings changes input validation, not KDF,
nonce or authenticated wire formulas. Existing canonical recipients retain
their representation and RNG consumption order.

## Checks and limits

The follow-up for 0.0.5 also fixes:

- TLV fields/readers/writers, editing pieces and packing requests no longer print
  their private contents through `Debug`, including owned wire requests.
- RSA-OAEP uses fixed-width arithmetic for its secret encoded message. Named
  secret values are wiped, avoiding recoverable OAEP data in freed heap limbs.
  This does not prove erasure of compiler-created stack copies.
- Streaming encryption rejects zero chunk capacity before callbacks or RNG use.
- Header assembly rejects a chunk size or recipient different from the plan;
  otherwise it can derive a different payload key or seal to the old recipient.
- X-Wing Seal requires a canonical classical recipient coordinate before RNG
  use. The raw X-Wing primitive and its frozen combiner remain unchanged.

Ten new regressions fail against the published 0.0.4 source and pass after
these fixes. Two private allocator checks reproduce OAEP residue with a
synthetic modulus and a real RSA key in registry 0.0.4, and pass after the fix.
An arithmetic compatibility test covers RSA-2048, RSA-3072 and RSA-4096.
The updated workspace passes 692 tests, with 15 existing ignored tests;
Clippy, Rustdoc and the pure-core WASM build pass. Frozen artifacts are unchanged.

The review used separate public source checkouts. Native tests include existing
KAT and golden vectors, malformed signed headers, low-order keys and parser
mutation tests. Clippy, Rustdoc with warnings denied, a pure-core WASM build,
and dependency license/advisory/source checks passed locally. The full 0.0.4
workspace release-mode run passed 681 tests, with 15 existing ignored tests.

A separate bounded property harness passed 13 tests. It checks K10 and nonce
derivation against separately composed primitives, commitment checks, domain/AAD
binding, rollback behavior, failure cleanup, signed headers, and P-256 forms.
It verified 33,153 Merkle leaf proofs across 257 tree shapes and 5,000 stateful
tree operations. Deterministic mutation loops covered 10,000 format inputs,
10,000 crypto inputs and 10,000 SDK inputs; a hybrid mutation test covered
2,273 bytes. These counts describe test inputs, not a security guarantee.

SDK checks cover 10,928 envelope bit mutations, 1,366 truncations, purpose and
context binding, low-order keys, the 16 MiB boundary, and simulated entropy
failure on each of the two RNG draws. Eight Python ABI tests use a real native
library and valid caller-owned buffers, including rejection without output
writes and allowed input/output overlap after copying.

These are implementation checks, not an independent cryptographic audit.
An additional audit reproduced the defects above, but its extended fuzzing
continuation was interrupted by a platform filter. No completed instrumented
fuzz campaign or timing/side-channel proof is claimed here.
